# 地图编辑源交付规范

给制作地图的美术看。按本文交付的存档，烘焙器（`:baker`）能直接烘成服务器用的地图版本；不合规的存档会被烘焙器拒收，并给出出错的区块坐标。

对应需求：`docs/DESIGN-M3.md` 的 `REQ-M3-020`、`REQ-M3-022` 与 `API-M3-003`。本文随烘焙器的规则更新，两者不一致时以烘焙器的实际行为为准，并回来改本文。

## 1. 存档要求

| 项 | 要求 | 不满足时 |
| --- | --- | --- |
| 游戏版本 | 原版 Java 版 26.2 存档，每个区块的 `DataVersion` 都是 4903 | 退出码 2，提示先升级 |
| 生成状态 | 交付范围内每个区块都生成到 `minecraft:full` | 退出码 2，给出该区块坐标 |
| 区块压缩 | `server.properties` 的 `region-file-compression` 保持默认 `deflate` | LZ4 压缩的区块退出码 2 |
| 超大区块 | 不能有外置的 `.mcc` 区块文件（单个区块超过 1 MiB 时原版会外置） | 退出码 2 |
| 方块与生物群系 | 只用原版 26.2 的方块和生物群系，不装任何增加方块或群系的模组、数据包 | 退出码 2，给出未知的名字 |
| 维度 | 地图做在主世界（`dimensions/minecraft/overworld/`） | 找不到该维度时退出码 2 |
| 可用高度 | 所有方块、方块实体（箱子、告示牌等）和实体（展示框、盔甲架等）都在 **y −64 到 191** 之内，共 256 格。y 192 到 319 必须全是空气 | 退出码 2，报出区块坐标、越界的方块或实体和它的 y |

服务器的世界只有 256 格高，烘焙器只取 y −64 到 191 这一段。原版主世界最高到 y 319，自然生成的高山可能伸到 y 192 以上，交付前用 WorldEdit 把这些山顶削掉。y −64 的基岩层和地下的深板岩都在范围内，不用动。

整张图都要做在更高处时（比如浮空岛），可以让程序用 `--min-y` 把这 256 格整体上移，例如 `--min-y 0` 取 y 0 到 255，那时 y 0 以下也必须全是空气，包括原版的基岩与深板岩。`--min-y` 必须是 16 的倍数，交付时说明用的是哪个值。

## 2. 处理顺序

交付前按顺序做完下面三步，顺序不能换：

1. 存档来自旧版本时，先用原版 26.2 专用服务端升级：`java -jar server.jar --forceUpgrade --eraseCache nogui`，等它跑完退出。
2. 用原版 26.2 专用服务端加 Chunky 把交付范围预生成一遍，直到范围内每个区块都是 full，且原版光照已算完（区块的 `isLightOn` 为真）。**升级之后必须重跑这一步**：升级只改数据格式，不补生成。
3. 用烘焙器自检（见第 6 节）。退出码 0 才算可以交付。

预生成时范围外会留下一圈没生成完的区块，这是正常的。交付时说明范围（见第 3 节），烘焙器只检查范围内的区块。

## 3. 交付范围

交付时给出地图的区块坐标矩形：最小 x、最小 z、最大 x、最大 z，四个数都是区块坐标（方块坐标除以 16 向下取整），含边界。例：方块 x 0～4,095、z 0～4,095 对应区块 `0,0,255,255`。

烘焙器用 `--bounds 0,0,255,255` 接收这个范围。不给范围时，烘焙器取存档里所有区块的外接矩形，预生成留下的外圈会让它拒收。

## 4. 制作工具

默认 WorldEdit 7.4.5 + Litematica 0.28.8，地形底稿可以用 WorldPainter（它对 26.2 的支持还没核实，用前先出一小块走一遍第 2、6 节）。工具选择还在等拍板（`docs/DESIGN-M3.md` §28.1 F3），改了会更新本节。

## 5. 服务端数据标记

需要服务器处理的方块（带逻辑的门、战利品箱等），用 **DATA 模式的结构方块** 标出来。结构方块放在目标方块**正上方一格**，在结构方块界面里把模式切到 DATA，「元数据」一栏按下面的格式填：

```
<命名空间> <SNBT>
```

- 命名空间是程序登记过的处理器名，例如 `synaxis:door`。可用的名字由程序提供清单；写了清单上没有的名字，烘焙器退出码 2，并报出结构方块坐标和这个名字。
- SNBT 是这个方块的服务端数据，可以省略。例：`synaxis:door {locked:1b}`。
- SNBT 里不能写 `id`、`x`、`y`、`z` 这四个键，位置由结构方块决定。
- 目标方块本来就有方块实体时（比如箱子），SNBT 的内容合并到它原有的数据上，原有的物品、名字等保留。
- 结构方块正下方不能是另一个数据标记。
- 烘焙后结构方块本身变成空气，玩家看不到。

例：一扇门的下半格在 (10, 63, 10)、上半格在 (10, 64, 10)，DATA 结构方块放在 (10, 65, 10)，元数据 `synaxis:door {locked:1b}`。烘焙后 (10, 65, 10) 是空气，门的上半格带上 `synaxis:door` 处理器和 `locked:1b`。门这类两格高的方块只能标上半格，因为下半格的正上方就是它自己的上半格。

### 隐藏区域

远景（远处的地形轮廓）里不想让玩家提前看到的区域，用同样的 DATA 结构方块圈出，元数据写：

```
synaxis:hidden <x1> <z1> <x2> <z2>
```

四个数是方块坐标，两个角都包含在内。这个结构方块也会变成空气，放在哪里都可以。远景包由后续阶段产出，届时这些区域在远景里显示为外沿的最低高度和中性材质。

## 6. 自检

在仓库根目录执行。`<存档目录>` 是含 `level.dat` 的那一层；两个目录都写绝对路径，`:baker:run` 在 `baker/` 子目录里运行，相对路径会找错地方：

```
./gradlew :baker:run --args="bake --map-id <地图名> --source anvil:<存档目录> --bounds <minX,minZ,maxX,maxZ> --out <输出目录> --threads 8"
```

可用高度按第 1 节上移过时，在 `--args` 里加 `--min-y <值>`。

| 退出码 | 含义 | 怎么办 |
| --- | --- | --- |
| 0 | 烘焙成功，输出目录下出现 `<地图名>/<build_id>/` | 可以交付 |
| 2 | 存档不合格：版本不对、区块没到 full、范围内缺区块、压缩格式不对、标记写错、可用高度之外有东西 | 按错误信息里的区块坐标或结构方块坐标修改 |
| 3 | 某个区域烘焙失败，例如一个 16×16×16 的小节里用了超过 256 种方块状态 | 按错误信息里的坐标减少该处的方块种类，或者找程序 |
| 4 | 烘焙结果自检不通过 | 找程序，这是烘焙器的问题 |
| 5 | 同一内容的地图版本已经在输出目录里 | 不用重烘；要重烘就换输出目录 |
| 6 | 烘焙器的光照版本还没通过验证 | 找程序 |

烘焙器认得的处理器命名空间来自游戏模块：程序在游戏模块里登记一个处理器，自检命令就认得它的名字。目前游戏模块还没有登记任何处理器，要到 M3-C 阶段才有；在那之前存档里只要有数据标记，自检就会以退出码 2 报「not registered」，带标记的存档先交给程序代跑自检。

退出码 0 时，清单 `manifest.json` 里的 `verify.source_light_diff` 是烘焙器算出的光照与原版光照不同的格数。结构方块换成空气后，它自己那一格和正下方一格的光照必然变，这两格不计入；其余的差异交给程序看，不影响交付。

烘焙器每个线程约需 256 MB 内存。`:baker:run` 默认能用本机物理内存的四分之一，8 GB 内存的机器用 `--threads 8` 够用。退出码 3 且错误信息里有 `OutOfMemoryError` 时，把 `--threads` 减半重跑。

## 7. 实体

展示框、盔甲架、文字展示（`*_display`）这类静态实体照常在游戏里摆放，烘焙器会把它们原样带进地图，玩家进入区块时生成。玩家在游戏里打掉或改动它们，区块重新载入后会复原。
