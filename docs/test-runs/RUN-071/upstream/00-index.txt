# Where this branch differs from upstream, and why
- MoveMinecartPacket: upstream's commit message says LP_FLOAT, its code writes angle bytes; 26.2 uses ByteBufCodecs.ROTATION_BYTE
  (01, section 9), so angle bytes. The packing truncates like the engine's other entity packets ((byte) (deg * 256 / 360));
  vanilla's Mth.packDegrees floors, so a negative angle off the 1/256 grid lands one step apart. Not changed here.
- Hover items: in this fork RegistryKey's codec does not look the key up when encoding, so an engine value naming an entry the
  process registered itself (upstream's test case) already encoded before the fix. What threw before the fix is a Gson value: the
  Adventure SPI has no Gson to NBT conversion (02, ComponentHoverItemRegistriesTest). The new test covers that, and that the Gson
  value is decoded with the buffer's registries (cp7).
- #3382's debug packet and ItemStackTemplate changes do not apply: the debug package was deleted with REQ-005 (dfadb0731d) and
  ItemStackTemplate already writes the component patch (6507294e3e).
- Instance.java keeps its line count (docs/DESIGN-M3.md cites Instance.java:1302-1334, :1315, :1332), so the two transition lines
  are reordered rather than merged as upstream does.
