## 4. Change notes, one dependency at a time (what applies to this repository)

gradle-wrapper 9.7.1 -> 9.8.0 (release notes https://docs.gradle.org/9.8.0/release-notes.html, upgrade guide
https://docs.gradle.org/current/userguide/upgrading_version_9.html):
  highlights Java 27 support, reuse of Maven mirror settings, linked problem locations. Potential breaking changes from
  9.7: embedded Kotlin 2.4.0 -> 2.4.10, ASM 9.9 -> 9.10.1, Groovy 4.0.33, JaCoCo default toolVersion 0.8.15 (this build
  sets none, so ci.yml's jacocoTestReport moves to 0.8.15), task output listeners kept in the configuration cache,
  Kotlin object singletons in the configuration cache, toolchain path warnings, lazy Copy/Sync destinationDirectory.
  Deprecations: org.gradle.parallel implying parallel Tooling API model building (gradle.properties sets
  org.gradle.parallel=true; IDE sync only), external processes at configuration time (the one in this build is
  providers.exec in server-app/build.gradle.kts:74, which is allowed), build cache from the start parameter, Signature
  APIs, non-Named attribute types, macOS Intel. Security: Gradle's blog (2026-08-31, blog.gradle.org/gradle-security-
  subscription) says free security fixes go to the latest minor of the current and previous major only, and lists
  9.3.0 and later with no known advisory. The 2026-09-30 run of this PR already built and tested everything on 9.8.0.
org.slf4j:slf4j-api 2.0.19 -> 2.0.20 (2026-09-22, https://www.slf4j.org/news.html): the Marker add/remove methods are
  deprecated ahead of immutable Markers. No code here uses org.slf4j.Marker (rg), so -Xlint:all -Werror has nothing to
  flag; the strict job compiled every module.
com.tngtech.archunit:archunit-junit5 1.5.0 -> 1.5.1 (release notes in the PR): java.lang.IO counts as a standard stream
  access; caught exception types now count as type dependencies (#1725), which can add edges to the layering and module
  rules. The strict job ran all ArchUnit rules (root ArchitectureTest, :architecture-tests 20, the host and game log
  rules) on 14437d0b78's code: green, so no new edge breaks a rule today.
ch.qos.logback:logback-core / logback-classic 1.6.3 -> 1.6.5 (https://logback.qos.ch/news.html, GitHub releases v_1.6.4,
  v_1.6.5): 1.6.4 (2026-09-24) restores variable substitution in the scan attribute (logback.xml has none), handles
  stateful encoders and fixes races in OutputStreamAppender / FileAppender (the RollingFileAppender behind the
  AsyncAppender of logback-file.xml), fixes the LoggerContext logger count race, rolls AM/PM patterns twice a day (the
  pattern here is %d{yyyy-MM-dd}), warns when Jansi is missing (no JansiConsoleAppender here), removes the unused
  LogbackMDCAdapterSimple (LogbackConfigurationTest uses LogbackMDCAdapter). 1.6.5 (2026-09-30): fixes CVE-2026-104721
  (path traversal through MDCBasedDiscriminator values of a SiftingAppender, affects up to 1.6.4); nothing here uses
  SiftingAppender or MDCBasedDiscriminator (rg), so the shards were not exposed; Time / SizeAndTimeBasedRollingPolicy now
  delete old files that were never compressed when compression is on (logback-file.xml compresses to .gz with
  maxHistory 14, totalSizeCap 10GB: archives a crash left uncompressed are now cleaned up too); SimpleInvocationGate is
  marked for removal (not used here).
org.flywaydb:flyway-core / flyway-database-postgresql 13.7.0 -> 13.9.0 (https://documentation.red-gate.com/fd/release-
  notes-for-flyway-engine-179732572.html): 13.8.0 (2026-09-24) renames the application name to Redgate_Flyway, publishes
  drift results, and sets the pgjdbc properties ApplicationName and assumeMinServerVersion=9.1 on PostgreSQL connections;

  FLYWAY_USE_SYSTEM_PROXIES defaults to false and Flyway Report is on by default (both command line; flyway-core 13.9.0's
  default model still sets reportEnabled false, FlywayModel.java:96, and its plugin list has no report generator), init

  13.7.0. No 2026 advisory against flyway-core's own code turned up (the Jackson ones reported in 2026 come through
  flyway-commandline). The strict job ran server-app's 577 tests with the database (MigrationsDbTest and the store
  classes, 0 skipped) on 13.9.0: green.
