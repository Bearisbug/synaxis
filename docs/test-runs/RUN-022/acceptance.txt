== 审查在本轮抓到的真问题 ==
ClientPlayConnectionEvents.DISCONNECT 由 ConnectionMixin 在 channelInactive 的 HEAD 注入、直接在 netty 线程上 invoke；
而 rts:game 的负载处理器由 ClientPlayNetworkAddon#isOnReceiveThread 门在主线程的 PacketProcessor 队列上。
两者同写 UnitBindings 的 LinkedHashMap，且 UnitPicker.pick 遍历时可能被另一线程 clear。
改用 INIT（由 ClientPacketListener 构造器点着，而该构造发生在 handleConfigurationFinished 里、已 ensureRunningOnSameThread）
后两边同线程同队列，顺序问题一并解决。证据以 javap 在真实 jar 上逐条取证。
